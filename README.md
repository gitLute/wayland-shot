# wayland-shot — идентификация, активация и снимки окон нативно для Wayland/KDE

Набор отдельных CLI-скриптов для работы с окнами в KDE Plasma (Wayland)
без каких-либо X11/Xwayland-средств: только KWin scripting, Spectacle,
ImageMagick и tesseract.

## Состав

| Файл | Назначение |
|---|---|
| `kwinlib.py` | общая библиотека: запуск JS-скриптов в KWin, сбор результата из журнала, съёмка, OCR |
| `win_id.py` | идентификация окон: поиск по pid / подстроке заголовка, `--list` всех окон |
| `win_activate.py` | активация окна (фокус + поднятие) с проверкой активного окна |
| `shot.py` | скриншот активного окна или всего экрана через Spectacle |
| `ocr.py` | обёртка над tesseract: текст (psm 6) и слова с координатами (psm 11/tsv) |
| `shoot.py` | оркестратор: pid → идентификация → активация → скриншот → контроль размера и маркера → ретраи |

Все скрипты независимы, имеют `argparse` и понятный usage в docstring.
Зависимостей Python нет (только стандартная библиотека).

## MCP-сервер (ветка `mcp-server`)

В подкаталоге `mcp-server/` лежит та же наработка, оформленная как
устанавливаемый MCP-сервер (Model Context Protocol) для LLM-агентов:
пакет `wayland-shot-mcp-server` с 10 инструментами (окна, активация, снимки,
OCR) и ресурсами `screenshot://`. Корень репозитория остаётся CLI-набором,
`mcp-server/src/wayland_shot/kwinlib.py` — развитие `kwinlib.py` отсюда
(диагностика ошибок OCR и сторож родительского процесса). Подробности —
`mcp-server/README.md`.

## Как это работает

KWin не отдаёт список окон по D-Bus напрямую. Нативный способ — скриптинг
оконного менеджера через QDBus-интерфейс `org.kde.kwin.Scripting`:

    qdbus org.kde.KWin /Scripting org.kde.kwin.Scripting.loadScript <путь> <имя>
    qdbus org.kde.KWin /Scripting org.kde.kwin.Scripting.start
    qdbus org.kde.KWin /Scripting org.kde.kwin.Scripting.unloadScript <имя>

`loadScript`/`start` ничего не возвращают, поэтому JS-скрипт печатает
результат через `print()`, который KWin пишет в собственный журнал
(`journalctl --user ... _PID=<kwin_wayland>`), а Python опрашивает журнал
с таймаутом и собирает строки с маркером `KJS_RESULT <json>`. Маркер
уникален на каждый запуск, что исключает подхват «чужих» строк соседних
вызовов.

**Важное ограничение KWin 6 (движок QJSEngine):** в JS-скриптах нет API
записи файлов (нет глобальных `writeFile`/`process`/`Qt`), поэтому результат
материализуется в файл на стороне Python (`win_id.py -o win.json`). По этой
же причине в JS-шаблоны подставляются только числа и ASCII-ключи: заголовки
и пользовательский текст (в том числе кириллица) обрабатываются в Python и
в JS никогда не попадают.

В KWin 6 в объекте окна нет методов `requestActivate()`/`activate()`;
работают присваивание `workspace.activeWindow = окно` и
`workspace.raiseWindow(окно)`. В `kwinlib` реализована цепочка из всех
четырёх способов, поэтому код совместим и с KWin 5.

## Использование

### Идентификация окон

    ./win_id.py --list                       # все окна, JSON в stdout
    ./win_id.py --pid 90749                  # окно процесса
    ./win_id.py --title "Kate"               # по подстроке заголовка
    ./win_id.py --pid 22927 --title make_scheme   # комбинация фильтров
    ./win_id.py --list -o win.json           # сохранить результат в файл

Код завершения: 0 — найдено, 1 — совпадений нет, 2 — инфраструктура
недоступна (нет kwin_wayland / qdbus / журнала).

### Активация окна

    ./win_activate.py --pid 22927            # по pid
    ./win_activate.py --title "Kate"         # по подстроке заголовка
    ./win_activate.py --index 3              # по индексу в windowList()

После каждой попытки активное окно проверяется отдельным скриптом
(`workspace.activeWindow`); при несовпадении — повтор (`--retries 3`).

### Скриншот

    ./shot.py -o win.png                     # активное окно
    ./shot.py --fullscreen -o screen.png     # весь экран (фолбэк)
    ./shot.py --active -o win.png --delay-ms 400

### OCR

    ./ocr.py image.png                       # текст (psm 6, rus+eng)
    ./ocr.py image.png --psm 11 --format tsv # слова с координатами
    ./ocr.py image.png --format tsv --min-conf 60 -o words.tsv

Формат `tsv`: `слово TAB уверенность TAB left TAB top TAB width TAB height`
(координаты нужны для будущих кликов; сам клик не выполняется).

### Оркестратор

    ./shoot.py --pid 22927 -o shot.png
    ./shoot.py --pid 22927 --title Kate --marker Untitled -o shot.png
    ./shoot.py --pid 22927 --expect-w 850 --expect-h 677 --marker Kate -o shot.png
    ./shoot.py --fullscreen -o screen.png

Алгоритм (перенос логики X11-скрипта `l2_shoot.py`):
1. идентификация по pid/заголовку через KWin scripting;
2. цикл до `--retries` (6): активация окна, пауза `--wait-ms` (800),
   снимок активного окна Spectacle, контроль размера кадра;
3. при совпадении размера — контроль OCR-маркера (если задан) и сохранение.

Код завершения: 0 — снимок ок, размер совпал, маркер найден (или не задан);
2 — размер совпал, маркер не найден (снимок всё равно сохранён);
1 — не удалось (окно не найдено / кадр не того размера / инфраструктура).

**Про контроль размера:** Spectacle снимает в физических пикселях и включает
рамку и тень окна, а `windowList()` отдаёт логические координаты (могут быть
дробными и не совпадать с пикселями из-за масштабирования дисплея и рамок).
Поэтому по умолчанию ожидаемый размер **калибруется по первому кадру** после
успешной активации и сверяется на последующих попытках — это ловит ситуации
«сняли не то окно / весь экран». Явный эталон задаётся `--expect-w/--expect-h`
в физических пикселях.

## Результаты проверки (KDE Plasma 6.7.5, реальная сессия)

1. `win_id.py --list` — KWin scripting отвечает, 6 окон реально перечислены
   (plasmashell, Firefox, Dolphin, Kate, Alacritty), JSON пишется и в stdout,
   и в файл (`-o`).
2. `win_id.py --pid 90749` и `--title "Kate"` — фильтры работают.
3. `win_activate.py --title Kate` / `--index 3` — окно переключается,
   проверка по `workspace.activeWindow` подтверждает pid 22927 / 6005.
4. `shot.py` — активное окно 2610x1490 (рамка включена), полный экран
   2560x1440; оба кадра валидные PNG.
5. `ocr.py` — текст распознаётся (rus+eng), слова с координатами выводятся
   (пример: `Kate 92.0 249 29 37 11`).
6. `shoot.py --pid 22927 --marker Untitled` — размер совпал, маркер найден,
   rc=0. С маркером `Zz9Xq` — rc=2 (снимок сохранён). С неизвестным pid —
   rc=1. В прогоне с фиксированным эталоном ретрай отловил первый «не тот
   кадр» (2610x1490) и на второй попытке получил нужный (850x677) — rc=0.

## Ограничения и что доработать

- **pid у нативных Wayland-окон** доступен через `windowList()` (проверено),
  но для служебных окон (панели, виджеты) он может быть -1 или указывать на
  плазмоиды — при поиске такие окна фильтруются только по заголовку/классу.
- **JS не может писать в файлы** (KWin 6/QJSEngine): результат получается
  через журнал kwin_wayland; если журнал недоступен (редкие настройки
  журналирования), скрипты не смогут работать.
- **`start()` запускает все загруженные KWin-скрипты сессии**: после каждого
  вызова наш скрипт сразу разгружается (`unloadScript`), но кратковременный
  запуск пользовательских скриптов возможен. Набор инструментов рассчитан
  на автономную среду.
- **Spectacle снимает окно с рамкой/тенью**, размер — в физических пикселях;
  поэтому ожидаемый размер калибруется по первому кадру (см. выше).
  При «мигании» композитора первый кадр может быть чужим — ретраи это
  компенсируют.
- **Только KDE Plasma**: вариант KWin использует D-Bus-интерфейс
  `org.kde.kwin.Scripting`; под GNOME/wlroots-композиторами не работает.
- Что доработать: клик по координатам слова из `ocr.py --format tsv`
  (нужен wayland-инпут, например `ydotool` в отдельном системном сервисе);
  автоопределение масштаба дисплея для пересчёта логических координат
  `windowList()` в физические пиксели снимка.
